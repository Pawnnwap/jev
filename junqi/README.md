# 军棋对抗环境 — JEV(决策模型) vs 树搜索规则 AI（暗棋）

二人陆战棋（军棋·**全暗棋**）完整对局环境：一个**规则裁判引擎**（双方物理上无法违规）、
一个**只凭公开信息思考**的 **α-β 树搜索规则 AI**，以及把 [jpt-4b 决策服务](../README.md)（`/v1/systemone`）
接成棋手的 **JEV 玩家**。每局自动生成自包含 HTML 可视化回放（双击即看，无需服务器）。

暗棋对**双方一致生效**：JEV 只看得见自己的棋子，RULE-AI 内部也不读敌子真名（从知识库采样"具体世界"再搜索）。
棋谱与 HTML 回放是**上帝视角**（双方真名），方便复盘。

## 快速开始

```bash
# 0) 前置: 决策服务在跑 (见仓库上层 README)
#    llama-server :8091 + jev_adapter :8090
#    ./start_jev.bat   (仓库根目录)

# 1) 规则自检 (18 项: 裁判规则 + 暗棋信息规则 + AI 公平性)
python junqi.py --selftest

# 2) 对抗赛: 4 局, 双方各执 2 先; AI 每步想 2 秒
python junqi.py --games 4 --ai-time 2.0

# 3) 看棋: 每局自动生成可视化回放 (上帝视角)
#    games/game_<时间戳>_g1.html  双击打开 → 播放/逐手/拖动进度/看战损
```

Python ≥ 3.10，仅需 `requests`。

## 全部参数

| 参数 | 默认 | 说明 |
|---|---|---|
| `--selftest` | — | 只跑裁判规则自检，不对局 |
| `--games N` | 1 | 对局数；第 1 局 JEV 执红先行，之后交替换边 |
| `--url` | http://127.0.0.1:8090 | JEV 决策服务（`/v1/systemone`） |
| `--ai-time` | 2.0 | 树搜索每步时限（秒），迭代加深在此时间内尽量加深（K 个世界共享此时限） |
| `--ai-depth` | 4 | 树搜索最大深度 |
| `--ai-samples` | 4 | RULE-AI 每步从知识库采样的"敌子世界"个数（暗棋：样本越多决策越稳，也越吃时间） |
| `--ai-refine` | 3 | **信念感知复评**的候选手数：走完这手后先更新我方知识库，再按新信念重采样世界重新评估（0 = 关闭） |
| `--ai-procs` | 0 | 并行子进程数（CPU 密集任务，线程无效；0 = 串行，建议 ≤ 核数−1） |
| `--max-plies` | 200 | 每局手数上限；打满按剩余子力价值判定（棋谱标注"判定"） |
| `--seed` | 7 | 随机布局种子（第 i 局用 seed+i） |
| `--out` | ./games | 棋谱/回放输出目录 |

## 可视化回放

每局生成一个**自包含 HTML**（`games/game_*_gN.html`，数据内嵌，可随意拷贝分享）。
棋盘视觉按开源军棋项目的成熟做法重制（参数参考 [phdsx/junqi](https://github.com/phdsx/phdsx.github.io)
的纸板风棋盘，走子箭头参考 [BitByBitG/siguo-junqi](https://github.com/BitByBitG/siguo-junqi)（MIT），
立体棋子参考 [samuelyuan/online-junqi](https://github.com/samuelyuan/online-junqi)（MIT））：

- 米黄纸板棋盘 + 印刷双框线：公路细线、**双轨枕木铁路**、圆形行营（带"行营"淡字）、
  双线大本营、前线山界群山与"山界"标注、半场楷体水印、行列坐标
- 红蓝立体瓷片棋子（底边厚度 + 倒角高光），平滑滑动重演每手，当前手金色光环
- 铁路远距离移动显示金色虚线箭头；当前手阵亡棋子在落点显示 ✕ 徽记（夺旗为金"旗"徽记）
- 播放/暂停/逐手/直达，速度 4 档，进度条拖动，键盘 `←`/`→`/空格/`Home`/`End`
- 着法列表（点击跳转），每手含**真实**战斗结算并按类型着色：`吃X / 触雷阵亡 / 炸弹同尽 / 同级互亡 / 夺旗!`
- 双方战损托盘实时更新；JEV 手显示前 3 概率，AI 手显示搜索深度与节点数

## 已实现的规则（裁判强制执行）

- 5 列(a–e) × 12 行(1–12)；行 1–6 蓝方半场、行 7–12 红方；行 6/7 间山界仅 b/c/d 三桥通行
- 每方 25 子：司令/军长/师长×2/旅长×2/团长×2/营长×2/连长×3/排长×3/工兵×3/地雷×3/炸弹×2/军旗
- 布局合法：军旗入大本营、地雷限本方后两排、炸弹不进前线排（随机布阵生成器）
- 公路一步；铁路直线任意远不可转弯；工兵铁路网内可转弯、不可越子
- 行营（每方 5 个，带斜线）：营内棋子不可被攻击
- 大本营（每方 2 个）：**只布军旗 + 排长**（公平性），入营即冻结不能再动，腾空后任何子都进不去
- 吃子：司令>军长>师长>旅长>团长>营长>连长>排长>工兵；同级同归于尽
- 炸弹与任何子同尽；地雷不能动，工兵挖雷存活，其余子触雷阵亡（雷保留）
- 胜负：夺军旗、或对方无子可走（困毙）；手数上限按子力判定

以上每条都有 `--selftest` 断言覆盖；双方只能从 `Game.legal_moves()` 中选择，
违规着法会被裁判直接拒绝。

## 暗棋信息规则（对双方一致）

- **只知己方**：文本棋盘里敌子一律是 `蓝?`（或 `红?`），只有被排除法收窄到唯一可能时才显示棋名
- **战斗结果不泄露身份**：攻击选项写 `敌子未明: 师长(吃)/炸弹(同尽)` —— 同级与炸弹结果等价（同尽），
  永远不可分辨；双亡只保留"同级 或 炸弹"两种可能
- **司令阵亡 → 其方军旗位置公开**；双司令对掉 → 双方军旗同时公开（大本营只布旗与排长，公开后两营身份一并确定）
- **敌子每动一次**即从可能集合里排除军旗与地雷
- **排除法剪枝**：某棋种全部阵亡、或存活名额被"已确证"占满 → 从其它敌子的可能集合中剔除
- 知识库 `Belief` 只由裁判入口 `apply()` 按可见事实更新；`make/unmake`（搜索）绝不触碰，
  因此搜索要么用采样世界的真值、要么用知识库，不会串味

## 两类棋手

- **JEV 棋手**：`state` 分节构建——规则要点、行营/大本营坐标与进攻方向、局势（手数/上限/**己方子力**，
  敌方只报存活/阵亡总数）、双方军旗（敌方未公开前只说"在两个大本营之一"）、地雷情报（候选雷位 + 可安全吃的滞留子）、
  己方存活清单与敌方"已确证"清单、最近 24 手**暗棋**着法、当前棋盘（敌子显示为 `?`）。全部合法着法作为 choice 选项，
  每条描述只给可能结果集合，并叠加**只看可能棋种**的走后风险评估
  （`移后会被蓝子吃掉(敌子可能: 司令/炸弹) / 移后可能与蓝师长同尽 / 入行营不可被攻击`）。
  发给 `/v1/systemone`，取概率最高的着法。接口连续失败 3 次回退随机并在棋谱标注。
- **RULE-AI**（纯规则，无模型）：
  - 评估：子力价值 + 推进度 + 行营占位 + 工兵保值 + 大本营冻结子浪费；**敌旗公开后**改为直接朝旗格加权（贴旗/守旗）。
  - 搜索：迭代加深 α-β（吃子优先排序，超时整层回滚）；**雷区惩罚随子力放大**（司令撞雷扣 ≈1.3×100 分），
    非工兵的"疑似撞雷"着法一律排到最后。
  - **暗棋公平性**：每手先从知识库采样 K 个具体世界（敌子棋种按可能集合随机落实，种子只由公开的着法史决定），
    在每个世界里分别搜索，再"每世界投自己最优一票"聚合，平票比各世界根节点精确分均值；
    根节点只对"真实局也合法"的着法打分。
  - **信念感知（对手会随信息改变走法）**：搜索内部模拟的每一手都会触发"司令阵亡 → 军旗公开"，
    于是模拟线里对方会立刻改为追已公开的旗营、且不再往占位营送子；根节点之后做一次**信念感知复评**——
    候选手法先在"我方信念副本"上真走一步（apply 会按战况更新信念），再按更新后的信念重采样世界评估，
    于是"这一手让我学到什么"被直接计价（探雷换信息、主动暴露司令的代价都会体现在后续走法价值上）。
    注意近似：世界内部假设对手在该世界里全知（对我们是偏保守的强对手），我方信念只在根节点推进一层。
  - **并行**：`--ai-procs N` 用进程池并行各世界的根节点搜索（CPython 受 GIL 限制，线程无效）；
    池惰性建立并复用，避免每手 spawn 的开销。
  - `junqi.py --selftest` 里有一道**不变性测试**：把两个敌子的真实棋种对调后，AI 的选择必须一模一样
    ——证明它读不到真相（含信念感知复评后仍然成立）。

## 实时对局台（浏览器）

仓库根目录 `start_junqi_live.bat` 一键起服务并自动开浏览器：

```bash
start_junqi_live.bat              # 起 JEV(8090/8091) + 对局台(8098) + 开浏览器
start_junqi_live.bat /NOJEV       # GPU 忙时跳过模型服务(仍可玩 RULE-AI / 人类)
start_junqi_live.bat /NOBROWSER   # 不自动开浏览器
stop_junqi_live.bat [/A]          # 停对局台（/A 连模型服务一起停）
```

- 双方棋手任意组合：**JEV / RULE-AI / 人类**（jev vs jev、rule vs rule、人机对战都行），
  人类在浏览器里点子走子，合法性由裁判 `Game.legal_moves()` 把关。
- 实时显示**每一步用时**（单步、总计、平均、最慢一步），人类思考时间同样计入。
- **上帝视角回放**：每局结束后点"上帝视角回放"，新标签页打开自包含回放（与 `--games` 生成的 HTML 同一套渲染）。
- **音效**：走子/吃子/同尽/夺旗/阵亡各有音效（OpenGameArt CC0，已裁剪压缩并内嵌成 data URI，离线可用），可一键静音。
- **着法动效**：远距离（铁路）着法画金色虚线箭头、刚走的子套金圈、落点显示 ✕ / 夺旗"旗"徽记（与回放页同一套实现，2.6s 后淡出）。
- 视角可选 上帝/红/蓝；选了对局视角时，**该视角下身份确定性 > 70% 的敌子**会直接标出"棋名 + 百分比"
  （金色标记；这是**该视角的后验推断**，不代表真实身份），其余仍显示 `?`。
- 棋盘横向 2 倍宽（格 128×64，整板 776×836，与回放页一致）。

## 实测战绩

- 明棋时代（历史记录）：默认设置下 RULE-AI 8:0 JEV；把选项描述改为如实战斗预告后，
  JEV 自杀送子消失、局均手数 +29%（55→76）；换 4B 引擎并强化 state 后局均 98–108 手、0 次送子。
- 暗棋改造后尚未跑完整对局统计（暗棋让 JEV 与 RULE-AI 同时变难，AI 侧还多了采样开销）。
